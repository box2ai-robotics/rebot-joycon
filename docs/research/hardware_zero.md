# 达妙硬件零位与断电保存

最新状态（2026-11-13）：用户撤销本地完成记录准入；运行只使用电机 Flash 零位，不读写 CAN/SN 记录。下文记录此前演进，当前实现与验证以 RUNBOOK 最后一节为准。

日期：2026-11-13。问题：用户要求七路零位写入电机且断电保留。

## 已核实依据

- [厂商 DM-J4340-2EC 使用说明书 V1.1，2026-09-08](https://github.com/dmBots/DM-J4340-2EC/blob/master/manual/DM-J4340-2EC%20%E5%87%8F%E9%80%9F%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E4%B9%A6%20V1.1%202026-09-08.pdf)：15 页，`FF FF FF FF FF FF FF FE` 为保存当前位置零点；16 页，存储参数使用 CAN ID `0x7FF`、数据 `CANID_L CANID_H AA 01`，返回同样的四字节，必须失能，Flash 写入最长 30 ms，会保存全部当前参数。
- [厂商 Python SDK](https://github.com/dmBots/motor-sdk/blob/main/Python%E4%BE%8B%E7%A8%8B/u2can/DM_CAN.py) 的旧示例仍发送 `AA 00` 并仅等待 1 ms，与手册有差异。本项目以明确的手册报文为实现依据，等待 `AA 01` 应答；不盲目重试写 Flash。

## 实现与边界

[校准入口](../../examples/0_calibrate_rebot.py) 默认执行硬件置零（`--hardware-zero` 可省略），对七路失能、置零、核验、保存、等待应答并重采软件零偏。执行硬件写入前备份现有两个文件及置零前位置。本轮按用户要求将无选项命令也改为硬件置零，取代原先只采软件校准的默认行为。

`--verify-hardware-zero` 在用户物理断电再上电且恢复同一机械姿态后，只读取七路位置，容差 ±0.02 rad，不写电机或本地配置。这是完成断电保持验收的必要步骤：保存应答和当前零位正确，不等于已经验证断电保持。用户设备具体固件版本尚未读取核对。

任何中途失败可能已改变部分硬件零点，须完成重新校准后才能控制。未修复纯软件校准对大偏移的限位坐标问题，本次采用用户选择的硬件置零路径。
