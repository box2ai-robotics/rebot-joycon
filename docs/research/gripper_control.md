## 2026-10-20：反馈超过 1 N·m 后的稳定处理建议

结论为设计建议，未修改控制代码或进行实机验证。1 N·m 可作为候选监测阈值，尚不能确认对电机、传动及物体安全；此前纯力矩命令约 1 N·m 而反馈达到 3.02 N·m，必须核对驱动型号、反馈比例与时序后再依赖该反馈实施保护。

推荐保留电机内部位置闭环，增加单向状态流程：低速闭合→接触/超限锁存→受控卸力→保持或故障。超限立即阻止目标继续向闭合端推进，重置轨迹内部目标，避免下一帧恢复闭合。仅冻结当前位置可能保留物体压缩与夹持力，不能当作卸力。必要时以有限速度、有限行程向已标定张开方向退让，配合经验证的较低刚度；卸力完成后固定目标，不逐帧追随力矩噪声。超过允许卸力行程/时限、反馈失效或持续严重超限进入锁存故障；撤销主动夹紧力可能掉落物体，需按使用场景定义终态。

避免“超过 1 就打开，低于 1 就继续闭合”的重复切换。接触判断可以去抖和设置回差，但独立的严重超限/失联路径不能被长时间滤波阻塞。低于释放阈值仅表示卸力完成，不自动重新闭合；重新夹取需明确的新操作边沿。保持力应低于保护阈值，具体数值、增益、速度与检测时间均需验证，不在此指定未经验证的默认值。

这是主机监督保护，无法阻止已经发生或通信时延内的峰值。若要求总驱动力矩受限，优先确认驱动内部对位置 PD 与前馈之和的电流/力矩限幅能力。[moteus 输出限幅](https://mjbots.github.io/moteus/troubleshooting/limited-torque/)明确提供这类内部限幅；[控制模式说明](https://mjbots.github.io/moteus/guides/control-modes/)解释内外环带宽差别，仅作架构依据，不意味着本机达妙固件支持相同字段。原 MIT 协议依据见下文专项检索。

## 2026-10-20：MIT 力矩控制专项检索

用户明确要求搜索 MIT 力矩控制方案。本节补充上一节的模式比较，重点区分“给定力矩”“位置闭环的总力矩限幅”和“反馈超限停机”。本轮未改控制源码、未连接电机。

### 查证结论与原始来源

1. **纯力矩控制是 MIT 的原生用法。** 厂商 DM-J4310 手册第 5 页明确 Kp=Kd=0 时用 t_ff 给定扭矩；第 7 页报文只包括位置、速度、Kp、Kd、前馈力矩，没有独立的总力矩上限字段。[达妙 DM-J4310-2EC V1.1 原厂手册镜像](https://damiao.enactic.ai/assets/files/dm-j4310-2ec-v1.1-zh-5d089e0b013d8e2fc203c5b670008a66.pdf)。因此主机裁剪 tau_ff 可以限制纯力矩命令，但不提供位置到位、速度上限或指尖冲击峰值保证；电流环仍在电机内部，并非电流开环。
2. **驱动端对 PID 与前馈之和限幅是已有实际实现。** moteus 文档明确 `maximum_torque` 对内部 PID 与 feedforward 的合力矩请求限幅，另有 `servo.max_current_A` 全局电流限制。[moteus 输出限幅](https://mjbots.github.io/moteus/troubleshooting/limited-torque/)。这是可借鉴架构，不是达妙寄存器/协议，不能将其字段直接加入本项目的 8 字节 MIT 报文。
3. **尽量保留电机内部闭环有带宽依据。** moteus 的控制模式文档提醒外部力矩控制带宽低于内部位置控制，并建议尽量利用内部控制器。[moteus 控制模式](https://mjbots.github.io/moteus/guides/control-modes/)。这是该控制器的实现在架构上的参考，不把其带宽比例移植为达妙实测数字。
4. **达妙 TMAX 应按映射范围理解。** 原厂 DM-J4340P 手册寄存器表将 TMAX 标为扭矩映射范围，OC_Value 标为过流保护；力位混控另提供电流请求饱和。[厂商手册第 6、8、13 页](https://doc.switch-science.com/media/files/5e033168-99f1-4d2d-b758-e03192a1f071.pdf)。不能推断 TMAX 限制 MIT 的 PD 总输出，也不能把过流停机当作连续限流。本机固件是否存在额外可配置总输出限制仍未验证。

### MIT 内可构成的方案

统一理想控制律为 `tau_request = Kp*(q_des-q) + Kd*(v_des-v) + tau_ff`。以下推导是在协议模型下的分析，真实命令还受量化、电流跟踪、摩擦、减速器效率和采样时延影响。

| 方案 | 实现与适用范围 | 限制 |
| --- | --- | --- |
| 纯力矩给定 | Kp=Kd=0，主机只裁剪给定力矩；可用于接触后的抓持阶段 | 空载时可能持续加速；必须另外管理端点、超速、接触丢失、超时。不是恒速闭合。 |
| 给定力矩＋电机端阻尼 | Kp=0，Kd>0，v_des=0，得到 `tau_request=tau_ff-Kd*v` | 消除位置误差环，阻尼在电机内完成。仅限制 tau_ff 不限制总力矩；反向运动时阻尼可能与给定力矩同向相加。 |
| 电机端位置/阻抗＋内部总输出限幅 | 驱动内部对 PD 和前馈之和进行限幅；外部提供轨迹 | 最直接满足位置跟踪与总输出限制，但需该固件支持，普通 MIT 帧本身不提供此字段。 |
| 实时外环计算并裁剪力矩 | 外部实时控制器计算位置/速度控制律，Kp=Kd=0，只下发裁剪结果 | 控制周期、反馈时延和闭环带宽必须设计与验证；不能仅把旧 Python 窗口线程的频率改大就认定稳定。 |
| MIT 监测监督保护 | 保留内部闭环，主机检测过力矩、失联等并锁存停止 | 故障响应而非连续限幅，不能保证通信延迟期间不超限；避免自动解除造成往复动作。 |

“给定力矩＋电机端阻尼”由上述控制律推导，不是本次找到并复现的达妙夹爪成品方案。若假定 `|v|<=V`，可用 `|tau_ff|+Kd*V` 得到命令模型中的保守上界；没有实际可保证的速度边界时，此式不能充当硬限幅。主机用旧反馈抵消阻尼也会重新引入延迟敏感问题。

### 对本项目的建议与尚缺证据

- 以前不稳定的是主机位置/速度反馈计算、滤波、串口与 GUI 共用周期的实现；纯力矩模式本身不能因此判为不稳定。恒力矩抓持和旧的外部位置 PD 是不同控制任务。
- 若要求全程位置跟踪且严格限制驱动力，优先确认实际驱动固件的总电流/力矩限幅能力；若没有对应 MIT 能力，不能仅靠裁剪 tau_ff 实现，应评估已讨论的力位混控或合适的实时控制架构。
- 若只要求接触后限力抓持，可设计“靠近时位置控制，确认接触后受限力矩抓持”的状态机；仍在 MIT 内变化 Kp/Kd/前馈即可，但切换须连续、接触丢失须处理，未实机验证，不能直接作为默认修复。
- 轴端力矩限制不等同指尖力限制；如果目标是准确限制物体受力，还需要夹爪传动几何/摩擦标定，必要时加入力传感器。

## 2026-10-20：MIT、位置速度与夹爪力矩保护方案比较

问题：BoxArm 是否使用 MIT；位置速度模式是否更适合机械臂；如何避免恢复此前不稳定的主机力矩闭环，同时获得夹爪保护。

本地事实：指定的 `/home/boxjod/Workspace/BoxArm/Examples/BoxArm_SDK.py` 的 `BoxArm_Control` 调用 `controlMIT(kp, kd, q, dq=0, tau=0)`。当前 [ReBot SDK](../../examples/ReBot_SDK.py) 同样采用电机端位置闭环；MIT 不等于只发力矩。当前夹爪 Kp=2、Kd=1，回中 Kp=1.6，零前馈；参考 BoxArm 普通夹爪 Kp=20、Kd=1。没有把参考增益整体照搬。4 号夹爪目标速度名义 2 rad/s，目标插补速度不等于实际到位速度。

协议区别：MIT 同时提供目标位置/速度、Kp/Kd 和前馈力矩，适合需要调节刚度阻尼的跟踪控制；其速度字段是速度目标，不是硬速度上限。位置速度模式采用电机内部串级环，速度字段表示运动限速，适合目标到位与限速需求，但不自动增加用户指定的力矩上限。纯速度模式没有位置目标，夹爪仍需端点/接触判断。六轴轨迹跟踪不能仅因夹爪问题就判断应全部换模式。[厂商 DM-J4310-2EC V1.1 手册，第 5–7 页](https://damiao.enactic.ai/assets/files/dm-j4310-2ec-v1.1-zh-5d089e0b013d8e2fc203c5b670008a66.pdf)

保护方案（架构建议，不是已启用功能）：

| 方案 | 特点与边界 |
| --- | --- |
| 保留 MIT，驱动器内部限制总电流/力矩 | 闭环仍在电机内；须确认该固件存在适用于 MIT 总输出的限幅参数。过流阈值可能触发失能，不等于连续限流。未核实本机支持情况。 |
| 7 号改为力位混控 | 发送位置、速度上限、电流上限；在驱动端限制电流请求，更匹配快速开合、接触后限力。电流比例不能直接当作 N·m，需本机最大电流/扭矩系数及输出轴换算；也不保证指尖瞬时峰值。 |
| MIT 加主机监测超阈值停机 | 可保留电机闭环，只在异常时采取动作。若实现，应锁存故障而不是自动恢复造成反复开闭；通信延迟期间可能超阈值，也可能释放物体，不能当瞬时限幅。 |
| MIT 限制目标误差/调整增益 | 可降低预计驱动力；测量时刻的预测不约束下个采样前的真实输出，不能宣称严格 3 N·m。 |
| 主机 PD 后裁剪力矩（旧方案） | Kp/Kd 发零、电脑计算并裁剪 tau；能约束发送命令，但当前位置闭环受 Python/串口/窗口周期影响。不可原样恢复为首选；若确需自定义力矩闭环，应在可验证实时性的控制平台重新设计与辨识。 |

力位混控依据：本项目 [Motor_CAN.py](../../examples/Motor_CAN.py) 已有 `control_pos_force` 与模式 4，速度编码乘 100、电流比例乘 10000；[上游 Python 库](https://github.com/cmjang/DM_Control_Python/blob/main/README_zh.md) 提供对应接口。厂商 [DM-J4340P-2EC 手册，第 6、8、13 页](https://doc.switch-science.com/media/files/5e033168-99f1-4d2d-b758-e03192a1f071.pdf) 描述电流请求饱和与力位混控报文。它是另一型号的协议证据，不能直接证明本机 4310 的实际固件支持；所查旧 4310 手册仅列三种模式。当前高层 SDK 仅允许 MIT，不能直接调用底层函数即认为切换完成。

两个陷阱：本地 `change_limit_param(..., TMAX)` 只改编解码量程，不向电机写配置，不能作输出保护；单侧改量程可能造成真实命令/反馈解释错误。厂商手册的 TMAX 也是“扭矩映射范围”，没有证据可据此认定它限制 MIT 的 PD 总和。`OC_Value` 是过流保护，不能与正常工作时连续电流饱和混称。

旧方案不稳定的分析：已确认的架构是延迟反馈下主机算力矩，叠加速度滤波、力矩滤波和同线程串口/窗口；相位滞后和摩擦可造成越过目标后仍施加原方向力矩，再反向纠正。具体贡献未用现场日志辨识，不能把振荡单独归咎于限幅或 MIT。此前示意负载测试通过没有证明实机稳定，此点应以用户现场反馈为准。

建议（推断）：六轴先保留 MIT；夹爪优先核实实际型号/固件是否支持力位混控，再确定电流限制换算。若不支持，核实 MIT 内部真实输出限幅；主机超阈值锁存保护可以补充，但不替代驱动端限制。当前速度偏慢可能与低 Kp、Kd=1 且 dq=0 的阻尼、目标插补和负载共同相关，不能直接以增大力矩上限解决。

验证状态：本轮只读本地源码并在线核对厂商手册/上游接口；未连接设备、未读取本机寄存器、未改源码/参数或执行运动。报告复用本文件，保留前轮历史。

**闭合目标被截断是已确认的软件缺陷。** 诊断开始时，编码器校准（历史本地文件 `examples/calibration/rebot.encoders.json`，不随仓库发布） 的夹爪闭合读数是 **+0.797093153 rad / +45.6701°**，而 配置（历史本地文件 `examples/calibration/rebot.json`，不随仓库发布） 的名义范围是 −270°…0°。原 `ReBotCalibration` 对两个端点做 `np.clip`，把实测闭合角裁成 0；离线直接加载结果确为 `open=-4.712388980, close=0`。1–6 号与共享 SDK 都从这里取闭合端点，因此无法命令到达标定的闭合位置。修复后以 `range_min` 作张开端点、实测读数作闭合端点，应用方向后生成限位，保留六轴零偏和校准文件；同时拒绝非有限、方向次序无效或超出 ±12.5 rad 编码范围的夹爪端点。

工作期间，编码器文件被外部更新（17:09:53 +08:00），闭合读数变为 **+0.957312882 rad / +54.8500°**，对应全行程 **5.669701862 rad**。新文件已保留；代码未写死任一闭合数值，并在新校准下重跑相同回归。后续重标定以文件实际值为准。

**离线复现了会妨碍减速的力矩逻辑，但尚未实测证明它是现场顿挫的唯一原因。** 源码与固定反馈结果：

## 当前控制信号如何发送

1. `pynput` 线程记录按键，主线程按经过时间更新目标；4 号直接更新关节角，5 号笛卡尔目标先经过 IK。
2. 每次 `ReBot_Control` 先复制七路目标，依次调用 `refresh_motor_status` 查询七路反馈；每次查询后 `read_all()` 非阻塞收包。夹爪反馈过期时额外等待最多 0.2 秒，仍过期则失能报错。
3. SDK 裁剪目标、计算增益，依次向电机 ID 1–7 调用 `controlMIT`。前六轴发校准转换后的位置 `q`、Kp、Kd，`dq=0, tau=0`；位置反馈闭环由电机执行。
4. 夹爪在电脑上用角度/滤波速度计算 PD（普通 Kp≤2、回中 Kp≤1.6、Kd≤0.08），扣除位置死区，执行 ±6 N·m 限幅，按 PD 请求力矩判断换向，仅对增力渐变、减力立即响应（第三轮修正）。夹爪 MIT 的 `kp=kd=q=dq=0`，只下发 `tau`；限幅预留一个编码量化步长。加大命令上限不会提高这些增益或渐变速度。
5. `Motor_CAN.controlMIT` 将五个量编码为 8 字节 CAN 数据，再封装成 30 字节 USB 串口帧，以 921600 baud 写入串口，由适配器发送 CAN。正常一轮为 **7 条反馈查询 + 7 条 MIT 命令**，顺序发送，不是同时到达。

控制发送仍与 IK、窗口处于同一主线程，没有独立实时发送线程。因此 100 Hz 是设定目标，不保证所有环境都达到；窗口/串口/IK 长时间占用仍可能延长命令间隔。终端新增的频率、角度、力矩及 IK 失败统计用于实机区分剩余问题。

配置入口为共享 SDK 的 `GRIPPER_MAX_TORQUE_NM`，更改后重启进程加载，影响真机 4/5/6 与 LeRobot examples 后端。

离线固定反馈验证中，持续大误差会平滑达到约 2.995116 N·m（预留报文量化余量），没有反复停机。固定 0.1 rad 误差、零速度时仅需约 0.18 N·m，把上限由 3 改为 4 N·m 对这条命令轨迹没有影响；4 N·m 仅为离线对照值，不是经过实机确认的推荐值。

因此，仅凭“一阵一阵”不能确认 3 N·m 限幅是原因。只有观测到命令持续贴近上限、实际运动仍不足，才有证据支持“限幅限制了驱动力”；即便如此也不能据此保证上调能消除顿挫。SDK 允许的 10 N·m 是协议编码边界，不等于夹爪的安全工作值。

本轮保留默认 3 N·m。力矩渐变、反馈延迟/反向清零及机械摩擦都是待核实因素，离线固定反馈测试不能复现或排除真实机械行为。

## 现场区分原因所需数据

后续在用户自行运行或授权的真机测试中，同步记录循环时间、目标角、实际角、速度、`_gripper_last_torque`（命令值）及反馈力矩：

- 命令远低于 3 N·m：仅上调限幅不会改变该时刻的 PD 命令。
- 命令在反向前反复归零：对照误差符号与反馈速度检查上述方向判断。
- 循环经常超过 20 ms：力矩渐变速率受单步时间裁剪进一步限制。
- 反馈缺失/超时报错：优先区分通信等待与力矩限幅。

不要用固定反馈的离线结果替代真实电机负载、温升和夹持力验证。本轮验证细节见 [RUNBOOK](../RUNBOOK.md)。


## 2026-11-13：4340 手柄张不开与减速比排查
